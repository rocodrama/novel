# 회차 마감

회차 원고(`正文/第NNNN章-제목.md`)가 써진 뒤 연재 가능한 상태로 마무리하는 절차다. 순서를 건너뛰지 않는다.

## 0. 대상 확인

- 작업 폴더는 작품 폴더다(`.webnovel/state.json`과 `CLAUDE.md`가 있는 곳). 아니면 사용자에게 어느 작품인지 묻는다.
- `CLAUDE.md`에서 플랫폼, 드라이브 경로, 노션 작품 페이지 위치, 시점·채팅 표기 규칙을 읽는다.
- 마감할 화 번호 N과 원고 파일을 정한다.

## 1. 분량과 AI 티 점검

```bash
python -X utf8 "<이 스킬 폴더>/scripts/check_episode.py" "正文/第NNNN章-제목.md"
```

- **분량 5,000자 미만이면 마감하지 않는다.** 장면을 새로 넣어 보강한다(개요의 必须覆盖节点과 本章禁区를 지킬 것). 같은 생각이나 묘사를 다른 장면에서 반복하지 않는다.
- **C-11(연결어미 뒤 쉼표)은 0개**로 만든다. 쉼표만 지우고 문장은 바꾸지 않는다.
- **C-8(대구)은 1개 이하**로 만든다. 가장 자연스러운 1개만 남기고 나머지는 직접 단언으로 바꾼다.
- 고친 뒤 다시 실행해서 "판정: 통과"를 확인한다. **새로 쓴 문장에 쉼표가 다시 생기기 쉽다.**

이어서 im-not-ai의 **humanize-scan 스킬을 정식으로 실행**한다(`humanize-korean:humanize-scan`, 인자는 원고 파일 경로). 스크립트는 일부 신호만 정규식으로 보고, humanize-scan은 6개 신호(C-8, E-1, C-11, I-4, E-2, F-5)를 실제로 고쳐 보며 전후를 잰다. 둘 다 돌렸다고 보고해야 "AI 티 점검 완료"다.

- humanize-scan이 보여 준 수정 중 **C-8, C-11, I-4, E-2, F-5는 원고에 반영**한다.
- **E-1(긴 문장 부족)은 반영하지 않는다.** 웹소설은 모바일 가독성 때문에 단문이 장르 관습이다. 보고서에는 "E-1 발동, 장르 관습으로 미반영"이라고 적는다.
- humanize-scan이 "많다"로 판정해도 `/humanize` 전체 윤문은 사용자가 요청할 때만 돌린다(문장을 길게 이어 붙여 웹소설 리듬을 해칠 수 있다).
- 이 플러그인이 없으면 사용자에게 알리고 스크립트 점검만으로 진행했다고 보고한다.

## 2. Codex 교차 검수

작품 폴더에서 실행한다. Codex는 파일을 읽기만 한다.

```bash
codex exec --skip-git-repo-check -s read-only "너는 한국 웹소설 편집자다. 이 폴더의 '正文/第NNNN章-제목.md'(N화 원고)를 직전 화 원고, '设定集/主角卡.md', '设定集/女主卡.md', '设定集/世界观.md', '大纲/第V卷-详细大纲.md'의 第N章 항목과 대조해 검수해라. 파일은 읽기만 하고 수정하지 마라. 셸 명령이 실패하면 다른 방법으로 파일을 읽어라.
다음을 한국어로 짧게 보고해라:
1) 직전 화·설정·개요와 어긋나는 점(本章禁区 위반, 연속성 오류, 실존 브랜드·플랫폼명 포함)
2) 번역투·AI 같은 문장, 어색한 표현 (원문 인용 + 고친 문장 제안, 최대 8개)
3) 독자 기준 몰입도/절단 강도 평가(한 줄)와 개선 제안 1~2개
치명적 문제가 없으면 '치명적 문제 없음'이라고 명시해라." 2>&1 | sed -n '/^codex$/,$p' | tail -60
```

- 설정·연속성 오류와 실존 브랜드·플랫폼명은 **반드시** 고친다.
- 문장 제안은 작품 문체(1인칭 구어, 의도한 과장·유머)를 해치지 않는 것만 받아들인다.
- 고쳤으면 1단계 점검을 다시 돌린다.
- 원고를 고치면서 개요와 어긋나게 됐다면 `大纲/第V卷-详细大纲.md`의 해당 화 항목도 맞춘다.

## 3. 회차 제목 점검

회차 제목은 목록에서 클릭을 부르는 장치다. 작품 제목처럼 **상황이 보이는 웹소설식 문장형**으로 짓는다. 한 단어나 요약형 제목("설마", "시청자 1명", "시작")은 쓰지 않는다.

- 그 화에서 **터지는 사건이나 가장 강한 순간**을 문장으로 담는다. 예: "초절정 미녀 전학생이 왔다", "냉미녀가 내 옆자리에 앉았다"
- 독자는 알고 주인공은 모르는 상황이면 주인공의 착각을 그대로 제목으로 쓰면 웃음 포인트가 된다. 예: "전학생이 하꼬 버튜버일 리가 없잖아"
- 결말을 다 말해 버리지 않는다(다음 화의 확인 장면을 빼앗지 않는다).
- 25자 안팎. 플랫폼 목록에서 잘리지 않게.
- 후보 2~3개를 만들어 사용자에게 고르게 하거나, 사용자가 맡겼으면 가장 강한 것으로 정한다.
- 제목을 바꾸면 원고 첫 줄 `# N화. 제목`과 파일 이름 `第NNNN章-제목.md`를 함께 바꾼다.

## 4. 커밋 (webnovel-writer-ko)

스크립트 경로는 설치된 플러그인의 최신 버전 폴더다.

```bash
S=$(ls -d ~/.claude/plugins/cache/webnovel-writer-ko/webnovel-writer/*/scripts | sort -V | tail -1)
W="python -X utf8 $S/webnovel.py --project-root ."
```

1. 이 화의 계약 문서가 없으면 만든다: `$W story-system "<이 화 목표 한 줄>" --genre "<state.json의 genre>" --chapter N --persist --emit-runtime-contracts --format json`
2. `.webnovel/tmp/`에 커밋 데이터 4개를 만든다. 가능하면 `webnovel-writer:data-agent` 서브에이전트에 맡기고, 직접 만들 때는 그 에이전트의 출력 스키마를 따른다.
   - `review_results.json`: blocking_count 0, summary에 Codex 검수 결과와 반영 내용, 분량
   - `fulfillment_result.json`: 개요의 CBN·CPNs·CEN을 planned/covered로, 개요 밖 장면은 extra로
   - `disambiguation_result.json`: `{"pending": []}`
   - `extraction_result.json`: 사건(떡밥 생성·회수, 관계 변화, 세계 규칙), 인물 등장, 장면(줄 번호는 1단계 출력의 `---` 줄 기준), 요약 100~150자
3. 실행하고 세 줄을 모두 확인한다.
   ```bash
   T=.webnovel/tmp
   $W write-gate --chapter N --stage precommit --format json        # "ok": true
   $W chapter-commit --chapter N --review-result $T/review_results.json --fulfillment-result $T/fulfillment_result.json --disambiguation-result $T/disambiguation_result.json --extraction-result $T/extraction_result.json   # "status": "accepted", projection 5개 done
   $W write-gate --chapter N --stage postcommit --format json       # "phase": "chapter_committed"
   ```
- 이미 커밋한 화를 고쳤을 때도 같은 명령으로 다시 커밋한다(장면 줄 번호를 새로 맞출 것).

## 5. 드라이브 백업

`CLAUDE.md`의 드라이브 경로 아래 `원고` 폴더에 `NNN화-제목.md`(세 자리 화 번호)로 복사한다. 제목을 바꿨다면 예전 이름의 백업 파일은 지운다.

## 6. 노션 갱신

노션 작품 페이지(NOVEL › 플랫폼 › 작품)를 찾아 갱신한다.

- **회차 관리 표**에서 해당 화 행: 제목, 상태(AI 초안이면 `초안`, 작가가 확인했다고 하면 `퇴고 완료`), 글자수(공백 포함), 핵심 사건, 절단 포인트, 메모(원고 경로, AI 초안 여부). 행이 없으면 새로 만든다.
- **5·6. 집필·퇴고** 하위 페이지의 "집필 메모"에 이 화 항목을 추가한다: 분량, 구성(장면 흐름 한 줄), 절단, 심은 떡밥, Codex 검수 결과와 반영 내용, 자체 점검 결과.
- 작품 페이지 맨 위 콜아웃의 "현재 단계"를 갱신한다.
- 노션 업데이트에서 `<b>`, `\~` 같은 저장 형태 때문에 문자열 매칭이 실패하면 페이지를 다시 읽고 저장된 형태 그대로 고친다.

## 7. 보고

사용자에게 짧게 알린다: 분량, 장면 흐름, 절단, 점검 스크립트와 humanize-scan 결과(발동 신호와 반영 여부), Codex 검수에서 고친 것, 커밋·백업·노션 결과. 원고가 AI 초안이면 작가 확인이 필요하다고 분명히 적는다.
